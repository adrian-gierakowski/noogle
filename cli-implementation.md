# Noogle CLI Implementation Plan

This document outlines the plan to implement a Command Line Interface (CLI) for Noogle, fulfilling the request in [Issue #39](https://github.com/nix-community/noogle/issues/39).

## Goal
Create a terminal-based interface for Noogle that allows users to search Nix documentation (including `lib`, `builtins`, `pkgs`, etc.) directly from their shell, offering a rich UI similar to the web experience.

## Architecture

### Language
**Rust** is the recommended language because:
1.  The project already uses Rust (`pesto`).
2.  It has excellent TUI libraries (`ratatui`).
3.  It can easily share data structures with the existing Rust code if needed.

### Data Source
The CLI depends on `data.json`, which contains the indexed documentation.
-   **Distribution**: The CLI should effectively "bundle" this data. In the Nix context, the `data.json` derivation should be an input to the CLI derivation.
-   **Loading**: At runtime, the CLI can load the JSON file. If installed via Nix, the path to `data.json` can be baked in or set via an environment variable.
-   **Structure**: The `data.json` file is a list of `Doc` objects. The CLI needs to deserialize this.

### Key Components

1.  **Search Engine**:
    -   Needs to replicate the search logic found in `website/src/components/SearchResults.tsx`.
    -   Fields to search: `meta.title`, `content.content`, and potentially splitting the title by `.` to match nested attributes.
    -   Libraries: `nucleo-matcher` (used by fzf) or `skim` for fuzzy matching. Or a simple "contains" check for exact matches if fuzzy is too heavy. `tantivy` might be overkill but is an option.

2.  **User Interface**:
    -   **Interactive Mode (TUI)**: Uses `ratatui` + `crossterm`.
        -   Search bar at the top.
        -   List of results on the left/main pane.
        -   Detail view (documentation preview) on the right or split pane.
        -   Markdown rendering for the documentation content.
    -   **One-shot Mode**: `noogle search <term>` prints results to stdout (useful for piping).

## Implementation Steps for the Agent

### Step 1: Project Setup
1.  Create a new directory `cli` (or `noogle-cli`) in the root.
2.  Initialize a Rust project: `cargo init --bin`.
3.  Add it to the workspace in `Cargo.toml` (if a workspace exists, otherwise independent or add to root `flake.nix`).
4.  Add dependencies:
    -   `serde`, `serde_json` for parsing.
    -   `clap` for argument parsing.
    -   `ratatui`, `crossterm` for TUI.
    -   `nucleo-matcher` or similar for search.
    -   `termimad` or `minimad` for rendering Markdown in the terminal.

### Step 2: Data Handling
1.  Define the structs matching `data.json`.
    -   You can look at `pesto/src/pasta.rs` (or `website/src/models/data/index.ts`) for reference, but you might need to adapt them since `pesto` structs might be for *generating* rather than *consuming* (though they should be close).
    -   *Tip*: The `data.json` structure is an array of objects.
2.  Implement a loader that reads `data.json` from a file path.

### Step 3: Search Implementation
1.  Implement a function `search(query: &str, data: &[Doc]) -> Vec<&Doc>`.
2.  The search should rank results. `meta.title` matches should generally rank higher than content matches.

### Step 4: TUI Implementation
1.  Set up the `ratatui` loop.
2.  **State**: `query` string, `results` list, `selected_index`.
3.  **Layout**:
    -   Top: Input box.
    -   Middle: Split view (Results list | Selected Item Content).
    -   Bottom: Help/Status line.
4.  **Events**: Handle typing in the input box to update `query` and re-run search. Handle Up/Down to change `selected_index`. Enter to maybe "expand" or open in browser?

### Step 5: Integration with Flake
1.  Update `flake.nix` to include the `cli` package.
2.  Ensure the `cli` package depends on `data-json` (generated by `pesto`).
3.  Pass the path of `data-json` to the CLI binary (e.g., via a const string injected at build time using `env!` or a wrapper script setting an env var).

## detailed Reference: Data Structure
The `Doc` object roughly looks like this (TypeScript reference):
```typescript
type Doc = {
  meta: {
    title: string; // e.g., "builtins.readFile"
    path: string[];
    signature?: string;
    // ... other fields
  };
  content?: {
    content?: string; // Markdown content
    // ...
  };
};
```

## Proposed CLI Commands
-   `noogle` (interactive TUI)
-   `noogle <query>` (quick search, prints list)
-   `noogle --json <query>` (outputs JSON for scripting)
